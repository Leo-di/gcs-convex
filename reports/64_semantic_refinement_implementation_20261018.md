# 教授要求与当前实现：候选落地、运动连接、整机语义验证

日期：2026-10-18。依据：`plan/id23_note.txt` 中约 05:03–42:40 的研究讨论。
本报告区分已有功能、本次新增功能和仍未解决的问题。未修改 GCS 核心算法，未移动正例场景中的桌子、杯子或障碍物，未推送 GitHub。

## 1. 教授的任务与实际差距

目标：初始机器人在 Room 1；仅底盘移动、机械臂收拢，找到 Room 2 内的合法停靠配置；随后底盘固定，机械臂在 Room 2 内完成抓杯和抬起。整机包含底盘、机械臂、夹爪的全部碰撞几何。

| 教授需要的能力 | 本次之前 | 本次之后 |
|---|---|---|
| 整机进入房间的配置谓词 | 已有精确几何支撑函数判定 | 保留；检查候选停靠、pregrasp、grasp、lift |
| 操作全过程的房间语义 | 已有凸盒的保守运动学下界与轨迹审计 | 保留并实际运行；不是只检查底盘中心 |
| 选择停靠与抓取配置 | 固定一个手工停靠点、单一抓取方向 | 固定网格生成多个 XY 停靠点 × 抓取方向，IK 求关节配置 |
| 初始状态到合法操作区的 bridge | 已有固定终点导航 GCS | 对候选逐个尝试导航 GCS；失败记录并搜索下一候选 |
| 连续阶段衔接 | 已有完整 base/arm/gripper 配置共享 | 保留并测量衔接误差 |
| 完整物理执行 | 绿色房间已有结果只完成参考轨迹验证 | 本次自由杯 SAP、真实双指接触执行通过 |
| 失败后搜索其他候选 | 没有外层搜索 | 新增有限预算候选搜索、进度记录、超时和失败审计 |
| 接口展示 | 没有本次完整展示 | 网页候选日志、数值结果和完整接触动画 |
| IRIS 操作区域 | 此入口用 guide-seeded 7D 凸盒 | 仍未改成 IRIS；不冒充已完成 |
| 通用多阶段语义计划补全 | 没有 | 仍没有；当前是给定两阶段任务的专用实现 |

本次不是新 GCS 算法，也不声称一般任务级完备性或全局最优。

## 2. 新增入口与冻结协议

- `src/semantic_refinement.py`：候选生成、整机筛选、调用现有 GCS/Drake、保留失败并继续搜索。
- `configs/scene_green_room_search.yaml`：独立配置；不含手工停靠候选。
- `src/green_room_gcs.py`：增加阶段进度、IK 目标整机检查、显式区分参考和物理成功。
- `tests/test_semantic_refinement.py`：候选独立于手工点、场景不被修改、目标合法不等于可执行、物理成功判据等回归测试。

冻结候选：x∈[0.25,1.35]、y∈[-0.45,0.05]，全局 0.1 m 网格；底盘 yaw 固定为初始 yaw=0；抓取 RPY 为 [0,0,0] 和 [0,0,0.15]。共 55 个停靠点 × 2 个抓取方向 = 110 个组合。按与杯子水平距离接近 0.85 m 的启发式排序；不是无偏采样，也不是对所有候选求最优。

完整规划预算最多 8 个候选，每个 300 s。协议、完整候选列表和源文件 hash 在规划前写入 `protocol.json`。每个候选保存独立配置、日志和结果。停止后剩余 `eligible` 表示尚未规划，不能计为成功或失败。

算法：配置级筛选 → IK 与目标语义 → 操作 guide → 官方 Drake 导航 GCS → 官方 Drake 7D 操作 GCS → 独立参考审计 → SAP 接触执行审计。没有失败后直接播放 guide 的分支。

## 3. 正例实际结果

结果目录：`outputs/results/semantic_refinement_20261018/`。

- 初筛 20 个组合因整机房间条件不满足而拒绝，90 个组合有资格继续规划。
- 第一个候选完整通过；其底盘配置为 [1.2,-0.1,0]，抓取 RPY=[0,0,0]。
- 这与旧手工点一致，但来源是冻结网格和排序；并不表明找到了新的最优停靠点。
- 剩余 89 个组合未运行完整规划，不可报告为 90/90 成功。
- 3 次 GCS 求解：导航、reach、lift；没有声称一次联合优化。
- 550 个参考帧，1655 个参考审计采样。
- 参考最小碰撞距离：0.002583607 m（全对最小距离，不等同于墙面安全余量）。
- 导航/操作阶段完整配置衔接误差：4.61e-22。
- 导航终点整机房间 residual：0.780 m（已扣除 0.02 m 语义 margin）。
- 物理操作全过程采样最小整机房间 residual：0.709748 m。
- 操作期最大底盘位置误差：0.007006 m。
- 双指接触抬起：通过；最终保持段双指接触比例：100%。
- 非预期接触记录：0（执行器每 10 ms 检查、力阈值 0.1 N；不是连续时间无接触证明）。
- 执行器力矩限制和滑移检查：通过。
- 自由杯物理执行：没有 attachment，初始化后没有杯子位姿重置。
- 物理仿真时长 57.9 s；规划约 27.45 s；外层候选尝试总耗时约 37.68 s（不含初筛）。

实际动力学仍使用理想全驱动平面底盘，不是车轮接触动力学。规划与参考审计中的持物模型使用刚性相对位姿，必须与实际自由杯物理执行区分。

## 4. 负例：目标配置合法，不代表存在当前规划器可找到的 bridge

结果目录：`outputs/results/semantic_refinement_closed_door_20261018/`。

这是独立、明确标注的负对照，不是正例调参：在共享门口加入封门障碍，其他几何保持一致；协议保存为 `outputs/results/green_room_closed_door_protocol_20261018.json`，实验内不再移动任何物体。

限制为 2 次完整候选尝试。两个不同抓取方向候选的目标配置与 IK 均通过，但都在 `motion_bridge_gcs` 阶段因当前导航区域图不连通被拒绝。系统从第一个失败继续尝试第二个，最后记录 `finite_search_exhausted_not_infeasibility_proof`。

没有生成伪成功动画，也没有将候选合法当作任务成功。这只验证有限候选/固定姿态规划的失败传播，不是一般 whole-body C-space 不可行性证书。

## 5. 不能省略的限制

1. **区域安全还未解决**：独立 holdout 中 reach 为 2/920 碰撞、4/920 原始抓取几何违规；lift 为 0/200 碰撞、3/200 原始抓取几何违规。房间语义违规均为 0。最终选择轨迹和实际执行通过，不代表全部凸盒安全。网页明确展示这些结果。
2. 手臂使用 guide-seeded 凸盒和官方 GCS；没有用 IRIS-NP2 替代此入口的区域构造，也没有声称 GCS 自己发现了全部机械臂路线。
3. 固定导航 yaw、固定收拢姿态、给定导航 lane；候选空间有限。没有完整 SE(2) 或自由 whole-body 导航。
4. 操作参考语义有保守整盒界；碰撞与实际接触执行语义是离散采样验证，不是连续时间物理安全证明。
5. 仅实现指定任务的 candidate grounding + bridge + constrained manipulation；未实现任意语义计划自动发现缺失 mode。
6. 没有新增公平的 no-semantic、endpoint-only、full-semantic 多场景统计基线；本次闭门负例不能替代这些实验。
7. 现有区域反例应优先解决；之后再研究通用补全与统计比较，不能据此声称论文贡献已完成。

## 6. 复现与展示

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 LCM_DEFAULT_URL=memq:// \
  .venv/bin/python -m src.semantic_refinement \
  --config configs/scene_green_room_search.yaml \
  --output outputs/results/semantic_refinement_new_run
```

输出目录必须是新目录，防止覆盖旧实验。默认运行接触动力学并保存完整 Meshcat 录制。`--no-dynamics` 只运行参考验证，结果明确标为 `reference_only_passed`。
