# 旋转安全导航接入完整 Grounding 搜索

日期：2026-10-19。承接报告 74 的两个固定目标回归。

## 本轮问题

上轮目标事先已知操作规划可行，只验证导航修复。本轮恢复完整外层候选搜索：给定场景、起点和任务，由程序按固定顺序选择底盘及抓取姿态，拒绝失败候选，直到获得完整可执行轨迹或预算耗尽。

这对应教授的流程：候选 base/grasp pose → IK grounding → 整机目标语义 → 连续操作规划 → 初始状态到目标的 motion bridge → 拼接检查 → 物理执行。计算上先检查操作、再计算导航；执行上仍然先导航、后操作。

## 冻结方案

- 沿用三种隔板宽度 0.15、0.30、0.45 m，未移动杯子、桌子、障碍物或起点。
- 每场 108 个底盘/抓取候选：底盘 x、y、yaw 与抓取朝向组合；yaw ∈ {−0.2,0,+0.2} rad。
- 固定按导航距离、底盘 yaw、抓取朝向编号和坐标排序。没有按新实验结果重排。
- 各场 600 秒总预算、每候选 300 秒；并行运行三场，保留所有失败及超时。
- 使用 `rotation_safe_gcs`：OMPL 引导、旋转位移界椭球覆盖、官方 Drake GCS；操作沿用 IRIS-NP2/GCS。
- 导航构造的引导余量为 3.01 cm，区域余量为 2.01 cm；该更保守构造可能排除仅在较小余量下存在的路径。失败不等于任务不可行。

原始目录：`outputs/results/rotation_safe_search_20261019`。场景、协议、运行前源码及 SHA256 已保存。

每场 60/108 个候选通过整机目标与碰撞初筛，三个 yaw 各通过 18、24、18 个。这些是候选数量，不是任务成功率分母。

## 新增实际执行语义回放

`src/audit_semantic_execution.py` 读取实际物理执行记录，在独立场景上下文中重建每个 base/arm/gripper 构型，用同一整机几何 oracle 重新计算包含余量。

- 初始状态及导航途中允许位于 Room2 外，负 residual 不直接判任务失败。
- 导航末样本及开始操作时应满足整机入室。
- 操作阶段全部实际样本应满足房间包含条件。
- 输出首次整机入室时刻、操作开始时刻、阶段最小余量、最紧碰撞几何和两指接触力。
- 逐帧结果写入 CSV，与原物理执行的最小余量进行一致性检查。

这是使用同一 oracle 对日志进行独立重算，不是独立几何算法，也不是连续时间形式化证明。房间是 XY 边界的竖直棱柱；余量已经扣除 2 cm。原日志阶段 `whole_body_carry_to_dropoff` 在当前任务中仅表示原地持物保持，不代表已完成运输。

新增单元测试确认导航阶段的负 residual 不会被误算为操作违规，同时操作阶段短暂越界不能被阶段平均值掩盖。

## 结论边界与后续

这次完成了从固定目标回归到自动候选搜索的集成验证，且有实际执行的阶段语义证据。三场仍是已使用过的相关开发场景，不是留出泛化测试；搜索排序、引导余量和实现与旧固定 yaw 方法不同，不能直接报告统计加速比、成功率优势或 GCS 对其他规划器的优势。

下一步应预先冻结更独立的场景与对照：统一初始状态、候选、预算、物理要求，仅改变语义策略，检查是否排除了人类不希望的几何可行解。当前没有新增长时域多物体任务、自动语义发现或全任务一次联合 GCS。

新增阶段语义测试通过；三条新物理轨迹重算通过，上一轮两条非零朝向轨迹也用于回放工具回归并通过。导航和操作核心算法本轮未修改。
