# 七维语义构型空间：Visibility Clique Cover 区域生成对照

本轮检验的问题是：在同一 3D 场景、同一全臂语义约束和同一 GCS 下，文献中的可见性团初始化能否改善有限凸覆盖及查询成功数。它不是 GCS 与其他规划器的对比，也不是新的 GCS 算法。

## 方法来源与适配边界

采用 Werner、Amice、Marcucci、Rus、Tedrake 的 [Approximating Robot Configuration Spaces with few Convex Sets using Clique Covers of Visibility Graphs](https://arxiv.org/abs/2310.02875)，Algorithm 1 和式 (1)。下载的论文及 Drake v1.57.0 对应源代码保存在 `data/visibility_clique_review/`。

流程为：在尚未覆盖的可行构型空间中均匀采样 → Drake VisibilityGraph 的离散边碰撞检查 → 反复求解最大团整数规划并删除已选顶点 → Drake 最小体积包围椭球 → Drake IRIS-NP2 膨胀 → 独立原场景审核 → Drake GCS。

最大团整数规划使用 SciPy/HiGHS：最大化所选顶点数，对每个非邻接顶点对约束两者不能同时选择。仅接受最优终止，设置零相对 MIP gap 和每次 120 秒上限；超时不会悄悄退化成启发式结果。逐次最大团最优不意味着整体团覆盖最优。若椭球中心发生碰撞，按论文及官方实现移到团内最近的构型，保留椭球矩阵。

官方 `IrisInConfigurationSpaceFromCliqueCover` 当前禁止 IRIS-NP2 自定义参数化。这里适配其流程，用原有仿射映射将七个独立关节位置嵌入包含底盘、夹爪和自由杯子的 19 维 plant positions。可见性检查在完整场景中执行，椭球和区域在七维中计算；映射保持直线段。没有用七维空间的低维切片替代全维空间。

相对论文的区别：使用后续 IRIS-NP2；只做预定的一轮覆盖、四次新区域调用，不运行到论文覆盖率终止阈值；两组共用两个缓存端点区域。这是有明确预算的文献方法适配实验，不是整篇论文的复现。

## 预先固定的对照

- 原始双房间场景，固定底盘，七个 iiwa 关节完整限位，杯子静止、夹爪张开；不允许机器人碰杯。
- 两组均约束整个机械臂/夹爪不得越过 x=0，规划语义安全余量 2 mm。
- 共用上一轮 `arm_cspace_research_v2` 已审核的起点、终点区域；其费用作为共同历史成本，不计入新增计算时间。
- 随机组从相同构建样本池取前四个可行、尚未被共用区域覆盖的构型，以 0.01 rad 球初始化。
- VCC 组用 192 个同池构型建立可见性图，取四个至少含八点的团和对应满维椭球。
- 两组各四次 IRIS 调用，四进程；IRIS 参数及编号对应的随机种子一致。调用次数相同，不是墙钟时间相同。
- 新区域使用 1,000 个独立抽样构型审核，发现物理碰撞或语义违反就拒绝，不补跑直到成功。
- 测试数据在区域生成前保存：2,000 个独立均匀可行构型；其中前 24 个构成 12 对固定测试查询。此外保留原任务作为查询 0。
- GCS 保持三次 Bézier、相同时间/路径代价、关节速度界和 rounding 设置。

区域覆盖率的分母是完整关节限位盒中满足当前碰撞与语义约束的均匀抽样构型；不等于工作空间面积覆盖率。测试查询的真正全局可解性未知，失败不能当作任务无解。独立记录端点未覆盖、区域图不连通和求解/审核失败。

## 验证与局限

最大团整数优化与小图穷举结果对照；七维仿射映射的边检查与完整场景直接检查对照；保留原来的七关节独立性、语义适配和满维审核测试。成功轨迹再独立检查 Bézier 控制点区域包含、解析导数控制点速度界、位置连续和目标值重算。

数值边碰撞检查、IRIS 概率过程和抽样审核不构成严格连续碰撞安全证明。仅一个覆盖构建随机种子、12 对测试查询，不能据此声称稳定的统计成功率优势。当前固定底盘、无接触参考轨迹，也不是完整 pick–carry–place 动力学任务。

## 实测结果

| 指标 | 随机种子 + IRIS-NP2 + GCS | VCC 初始化 + IRIS-NP2 + GCS |
|---|---:|---:|
| 新区域尝试 / 接受 | 4 / 3 | 4 / 3 |
| 总接受区域（含两个共用区域） | 5 | 5 |
| 2,000 个测试可行构型覆盖 | 891（44.55%） | 965（48.25%） |
| 初始 12 对测试查询成功 | 0 / 12 | 0 / 12 |
| 后续固定追加 100 对查询成功 | 18 / 100 | 23 / 100 |
| 原任务查询 0 | 通过 | 通过 |
| 新区域膨胀及审核墙钟 | 197.29 s | 39.94 s |
| 可见性图额外耗时 | 无 | 190.72 s |
| 最大团与椭球额外耗时 | 无 | 0.66 s |
| 原任务采样路径长度 | 3.81864 rad | 3.74410 rad |

新增覆盖构建阶段的时间合计约 197.29 s 与 231.32 s（不含两组共同的采样、缓存区域成本，也不含查询规划）。因此 VCC 本次单区域膨胀更快，但计入可见性开销后没有总时间优势。

可见性图有 12,143 条无向边；四个团含 67、27、22、17 个构型，四次 MIP 均最优终止、gap=0，椭球中心均无需调整。共享的两个区域本来覆盖 659 / 2,000 个构型。最终两组共同覆盖 841 点，随机组独有 50 点，VCC 独有 124 点，两组都未覆盖 985 点；不是区域嵌套比较。

### 追加查询的透明说明

看到两组初始结果均为 0 / 12 后，保持区域、GCS 参数不变，先保存追加协议，再使用已保存测试样本的第 24 至 223 个构型构成另外 100 对查询。没有按可解性或方法优劣挑选；原先 12 对失败完整保留。

追加 100 对中，两组共同成功 16 对，随机组独有成功 2 对，VCC 独有成功 7 对，两组均失败 75 对。合并初始查询后为随机组 18 / 112、VCC 23 / 112；原任务查询 0 不计入随机测试分母。

所有追加失败都归为 `endpoint_not_covered`：随机组 82 次，VCC 77 次。端点均被覆盖的查询，分别 18 / 18 和 23 / 23 通过，没有观察到区域连通情况下 GCS 求解失败。这里的结论是这批查询受区域覆盖限制，不能推广为 GCS 永远不会失败。单次构图和小规模配对测试也不足以证明稳定的成功率优势。

### 安全审核与拒绝记录

两组各有一个新区域在 1,000 点审核中发现一次碰撞，因此拒绝进入 GCS。

- 随机组 candidate 103：夹爪与 `shared_wall_lower_collision` 相交，最小距离 -0.025746 m。
- VCC 组 candidate 103：夹爪与 `shared_wall_upper_collision` 相交，最小距离 -0.032116 m。

它们不是微小容差误差，也没有被忽略。几何名字、样本索引和复核距离保存在 `rejection_witnesses.json`。IRIS 内部非线性求解未收敛警告保留在日志中。

原任务两条轨迹分别审核 1,633 和 1,677 个构型；追加成功轨迹分别共审核 21,944 和 28,514 个构型，均未发现碰撞或语义越界。所有成功轨迹的独立 Bézier 系数审核通过，包括区域包含、控制点导数速度界、位置连续和目标值重算；仍然不能把有限几何审核写成连续安全证明。

## 下一步依据

优先按 VCC 文献的外层循环，针对尚未覆盖的可行空间继续采样和区域膨胀，并在多个构图随机种子上比较固定预算下的覆盖率、查询成功率与总计算成本。当前单轮低预算实验不等于完整自适应覆盖算法。不要仅因原任务演示成功就认为算法达标，也不要把本轮结果当作 GCS 相对其他规划器的性能证明。
